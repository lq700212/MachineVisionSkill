# 上位机项目报价范式（上位机报价）

> 沉淀自苏州毅嘉 Audi cover module 固化设备上位机真实报价（2026-10）：
> IO 表 3 页核实 + VB 两套参考程序 9041 行体检 + 工价三级置信度调研 +
> 对内 11~15 天 / 对外 1 个月 / 对外 12.8 万（底线 10.5 万）成交框架。
> 弱模型照抄执行：脚本为主，AI 只做判断与写作，不许自创公式、不许编数字。

## 一、何时用我

- 用户说"看看这个项目要多久/多少钱""报个人天/工期""出个报价"；
- 手里有电气 IO 表（xlsx）、甲方参考程序（VB/旧上位机）、领导给了报价点；
- 需要把"报价思路"沉淀成可复用的内部文档或 skill。

## 二、先定口径（开工五问，不答不许开工）

1. **纯上位机还是含 PLC？**纯上位机必须在文档 §1 写死范围、§6 写排他，对外"程控"改称"上位机监控"。例外：上位机经 IO 耦合器做联锁放行等**上位机侧**程控、经客户书面确认后可称"上位机程控"，但 §1 必须定义程控边界、§6 照样排他 PLC 程序编写/修改（cases/002 实例）。
2. **CIM/过账含不含？**不含就写"预留接口、不含联调"，防默认含上；含则单独立项计价（见卡点 #10），联调轮次包干写死，超出按次。
3. **几站？什么部署拓扑？**IO 表只给 1 站时默认其余对称复制，单价另列，不对称逐站核价。必须追问**一机一线还是一机多线**：一机多线（如 1 台管 2 线）要加多线管理（多 PLC 连接/分线日志追溯隔离/视图切换）工作量，不许套对称复制单价（cases/002：B/C 共用 OP20 一机双线 +3~4 天）。
4. **工艺节拍多长？一次全上还是分批？**决定跟线天数与进场次数。
5. **现场谁配合？电工专人还是叫号等？**等人的时间不算我方工期（写进 §6）。

## 三、六步作业法（顺序执行，不许跳步）

### 第 2b 步：布局参考目检（有 PDF/图片就必做，与第 2 步可并行）

> 文字型手册 PDF 走 `pdf-analysis` skill；**本分支只管布局参考**（界面/图纸/手绘），靠目检不用脚本。
> PDF 用 Read 工具直接读（附件形态逐页看）；图片（png/jpg/微信截图直给，常见于 HMI 参考界面）同样用 Read 直读。三形态＋图片分支：

- **A. HMI 截图/设备照片拼的**：逐屏盘点填画面清单（屏名/控件数/数据源/弹窗与否），屏数不清先数屏。
- **B. 电气图纸类**：按图纸盘站点与信号回路数，回路数≈联调点数，回填 §1。
- **C. 手绘布局＋文字需求**：需求条目逐条转功能点，转不了的标"待澄清"进 §7，不许脑补功能。
- **D. 图片直给（HMI 参考屏照片/截图）**：按 A 同样逐屏盘点；屏与**文件名**一一对应（写清文件名），让经理能回查。
- 参考界面的反向用法（省钱证据）：屏上字段若在自家框架/融合版中全有对应（参数记忆/数据模型/登录体系），即证明**无新增接口与画面工作量**，本次不加价，只在 §1 贴清单＋§8/附录记一笔"已覆盖依据"（cases/002 实例：2 屏→P1/P2 零新增）。

- **A. HMI 截图/设备照片拼的**：逐屏盘点填画面清单（屏名/控件数/数据源/弹窗与否），屏数不清先数屏。
- **B. 电气图纸类**：按图纸盘站点与信号回路数，回路数≈联调点数，回填 §1。
- **C. 手绘布局＋文字需求**：需求条目逐条转功能点，转不了的标"待澄清"进 §7，不许脑补功能。
- 三形态统一输出画面清单（贴 §1）：

| 屏/图号 | 类型（简单显示/常规监控/复杂） | 控件/回路数 | 数据源（PLC/手动/接口） | 备注 |
|---|---|---|---|---|

- 复杂度→人力映射（经验系数，**首单必须用结算回填校准，不许当标准报**）：
  简单显示屏 0.5 天（指示灯＋文本，无交互）；常规监控屏 1 天（表格/曲线/报警）；
  复杂屏 1.5~2 天（配方/追溯查询/报表/多 tab）；新通讯协议 1~3 天/种；历史追溯 1~2 天。
- 目检铁律：数的屏必须和 PDF 页码/图号**或图片文件名**一一对应（写"PDF 第 N 页"/"文件名 xxx.png"），让经理能回查；看不清先要原图，不许猜控件。

- **实时铁律：每单必 fresh 搜，不许复用上次数字**（行情按季度漂移；上次是 2026-10）。

  4. `上位机/产线数字化 中标/成交 多少钱` → 同类成交锚（找到了直接对标 cases/ 案例）。

  - 【较实】招聘平台多样本月薪、论坛行规算法（天数×日薪+调试×1000）；

  - 【反例】模板套改低价——写清"不给源码不去现场"，变压价防御话术。

  每单结算后 1 周内按 `templates/case_record.md` 回填一案（匿名＋区间价），案例库越用越准。

## 四、报价阶梯公式（唯一口径）

- 对内成本（悲观口径，诚实）：`dev_max×日成本 + site_max×日成本 + travel_max + 分摊`。
- 对外合计 = Σ分项；锚价 = 合计（先报）；让步价 = 合计 − give（甜点成交）；底线 = floor（破了不签）。
- 让步池专款专用：运维项（先砍半年运维让 1 万）；再砍砍重构项（称融合优惠）；B 项（现场血汗钱）绝不让。
- 付款与工期：`3-4-3`，预付到账起 N 天（写自然日，含 buffer）；验收两节点。

## 五、红线（违反即返工，弱模型重点背）

1. **工价禁编＋实时**：无来源 URL+样本量+日期的数字不许进文档；软数据必须标"软数据"；
   每单 fresh 搜，复用旧数按编造处理；见 skills 仓库 AGENTS.md 同款铁律（硬件参数禁推测）。
2. **工具链禁外泄**：对外一律"融合重构"，不提 AI/工具/prompt；不给行对行 diff，只给功能对照表；证据对外只报文件名不报行号，更不给本地路径。
3. **无证据不指控**：体检 0 命中的项（如登录/密码）对外一个字不许提。
4. **纯上位机排他**：§1 定范围、§4 B/C 项括号备注、§6 单列"不含"，三处缺一即打回（quote_check 只查"不含+范围关键字"存在，写全靠人；--scope 见第 6 步）。
5. **两本账**：无现场拆分的报价一律打回（9 天教训）。
6. **文件编码 UTF-8**：终端 GBK 乱码是假象，判读只看 UTF-8 文件；内部报价文档放 untracked 的 docs/，`git add .` 禁止，防推上 GitHub。
7. **脚本输出 SOP 严格执行**：脚本 flag（模板页/有表头无数据/重复组/0 命中）必须进文档对应位置，不许"觉得没用"跳过。
8. **案例脱敏＋回填**：`cases/` 只记匿名＋区间价（客户实名/精确价/源码路径禁入）；每单结算后 1 周内回填，
   首单画面映射系数必须用结算校准后再当标准用。
9. **无参考不裸报**：没参考程序就走复用说明线（自家框架复用项＋新增量），两种作业线见第 1 步；只有口头需求先追输入。

## 六、话术库（ copy 即用，按项目改括号）

- 转换定性："不是换语言，是老程序带病，硬套新线会出事。"
- 七条骨架：双程序→一套；UI 线程节拍+MsgBox→后台化；N×M 行拷贝+死窗体→单复用件；写死→配置窗；残留引用/过时 HTTP→转正；VB+net48+0 测试→net8+回归+模拟；无登录→账号体系。
- 封还价："缺陷根除+架构重做，逻辑 1:1，有 CHANGELOG 和 N 例测试为证；坚持老程序直用，（冻屏/改代码/漏改）三类问题不承担售后。"
- 范围排他："本项目纯上位机，不做 PLC 程序与硬件电气；PLC 变更返工按天另计；等待不计工期。"
- 被模板低价压："那是不给源码不去现场的价，我们对标源码+驻场+质保的正规交付。"
- 被问"10 万不是说会拒吗"："10 万是单事项天花板；12.8 是两件事打包的锚价，奔 11 万成交去的，单项都没超行情。"
