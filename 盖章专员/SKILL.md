# 公章添加工具 v1.2.0

自动将公章图片添加到合同上——**支持四类输入**：文本版 PDF、扫描件 PDF（无文本层，
自动 OCR 建文字层）、图片文件（png/jpg/jpeg/bmp/webp，拍照件直接盖章）、Excel
工作簿（xlsx/xls/xlsm/xlsb，自动转 PDF 后盖章）。
**智能定位（默认开启）：给一枚公章就知道盖哪**——OCR 识别公章上的公司名，
自动匹配合同里该公司是甲方/乙方/卖方/买方等哪个角色，精准盖到该角色的盖章处；
精确匹配已有公章尺寸，支持旋转模拟真实盖章；盖完自动压平，公章不可被编辑软件
单独编辑。

## 功能特点

- **四类输入统一支持（v1.2.0）**：
  - 文本版 PDF：原管线直接处理
  - 扫描件 PDF（无文本层）：自动识别 → 150dpi 渲染每页 → 整页 OCR 建立隐形
    文字层 → 后续智能定位/压平与文本版完全一致；输出 PDF 文字反而可搜索
  - 图片文件（拍照件）：规格化为 A4 宽页面 + OCR 文字层 → 盖章压平后**渲染回
    同分辨率同格式图片**（章融入像素，不可移除）；指定 .pdf 输出则给 PDF
  - **Excel 工作簿**（xlsx/xls/xlsm/xlsb）：第 0 步调用本机 Office Excel COM
    执行「另存为 PDF」（等价人工在 Excel 中另存为 PDF）→ 之后定位/盖章/压平与
    文本版 PDF 完全共用；输出 `原名_已盖章.pdf`；本机没装 Office 时给出"手动
    另存为 PDF 后重跑"的兜底指引
- **智能定位（默认开启）**：OCR 识别公章公司名 → 匹配合同签署方（甲方/乙方/丙方/
  卖方/买方/供方/需方/出租方/承租方/发包方/承包方/委托方/受托方/招标人/投标人等）
  → 自动盖到该角色的"（盖章）"处，全程无需人工指定位置
- **自动检测公章**：扫描 PDF 识别已有公章（红色圆形印章）
- **关键词定位**：智能定位失败时的回退手段，搜索"签章"、"公章"等关键词定位签名区域
- **精确尺寸匹配**：从 PDF 中提取参考公章图片，用红色检测裁剪内容区域，确保新公章与已有公章视觉大小完全一致
- **RGB 转透明背景**：JPG/JPEG 等无透明通道的图片自动转为透明背景 RGBA，避免白色背景遮挡合同文字
- **智能裁剪**：去除新公章图片的透明 padding，只保留印章内容
- **旋转效果**：支持旋转角度，模拟真实盖章效果（默认逆时针旋转 20°）
- **自动定位**：计算对称位置（左侧公章 → 右侧对应位置）
- **防编辑压平（默认开启）**：盖完章自动把盖章页压平为"整页位图 + 隐形文字层"——公章与页面融为一体，PDF 编辑软件（Acrobat/福昕/WPS 等）无法单独选中、移动、删除公章，杜绝法律风险；隐形文字层保证文字仍可搜索、可复制
- **依赖自动安装**：首次运行自动检测并安装缺失依赖（国内镜像加速），无需手动 pip install

## 使用方法

```bash
# 全自动（推荐）：给合同和公章即可，智能定位+压平一次完成
python pdf_seal_stamper.py <合同PDF>
python pdf_seal_stamper.py <合同PDF> <公章图片>

# 扫描件 PDF（无文本层）：自动识别并 OCR，用法与文本版完全相同
python pdf_seal_stamper.py <扫描件PDF>

# 图片（拍照件）：默认输出 原名_已盖章.原格式（与原图同分辨率）
python pdf_seal_stamper.py <合同照片.jpg>
# 图片输入但想要 PDF 输出：显式指定 .pdf 输出路径
python pdf_seal_stamper.py <合同照片.jpg> <公章图片> <输出.pdf>

# Excel（报价单/订购单等）：自动用 Office「另存为 PDF」转 PDF 后盖章
python pdf_seal_stamper.py <报价单.xlsx>
python pdf_seal_stamper.py <报价单.xlsx> <公章图片> <输出.pdf>

# OCR 识别不准时，手动指定公章公司名（自动匹配合同角色）
python pdf_seal_stamper.py <合同PDF> <公章图片> --company "苏州华际光电科技有限公司"

# 手动指定盖到哪个角色（跳过 OCR 与角色匹配）
python pdf_seal_stamper.py <合同PDF> <公章图片> --role 乙方

# 指定输出路径
python pdf_seal_stamper.py <合同PDF> <公章图片> <输出PDF>

# 预览分析（不生成文件）
python pdf_seal_stamper.py <合同PDF> --dry-run

# 调整旋转角度 / 位置微调
python pdf_seal_stamper.py <合同PDF> <公章图片> --rotate 15 --offset-x 10 --offset-y -5

# 关闭智能定位，只用常规定位（参考章对称 → 关键词 → 默认）
python pdf_seal_stamper.py <合同PDF> --no-auto

# 不压平（公章保留为可编辑的独立图片对象，有法律风险，仅应急/内部核对用）
python pdf_seal_stamper.py <合同PDF> --no-flatten
```

公章默认图片路径为 `默认公章图片.png`（脚本同目录下），不指定公章图片时自动使用。

## 标准作业流程（最短路径，照抄执行即可）

**第 1 步：盖章**
```bash
python "<本skill目录>/pdf_seal_stamper.py" <合同文件> [公章图片]
```
（合同文件 = PDF / 扫描件 PDF / 图片 / Excel（自动转 PDF）均可；不指定公章图片=用
默认公章；只想预览位置不生成文件，加 `--dry-run`）

**第 2 步：逐行检查脚本输出，对照决策表行动**

| 脚本输出包含 | 含义 | 你要做的 |
|---|---|---|
| `输入类型: Excel 工作簿` 且后续有 `转换完成` + `转换后 PDF 输入类型: 文本版 PDF` | Excel 已自动转 PDF，之后定位方式与 PDF 完全一致 | 继续对照下面各行判断定位结果即可 |
| `❌ Excel 转 PDF 失败` 且给出"手动用 Office 另存为 PDF"提示 | 本机 Excel COM 不可用（缺 Office/pywin32） | 按提示手动在 Excel 里「另存为 PDF」，再把生成的 PDF 交给盖章流程重跑 |
| `输入类型: 扫描件 PDF（无文本层）` 或 `输入类型: 图片文件`，且后续有 `OCR 建立文字层完成` | 扫描件/拍照件已自动 OCR，定位流程与文本版一致 | 继续对照下面各行判断定位结果即可 |
| `⚠️  OCR 依赖不可用，无法建立文字层` | 扫描件/图片没有 OCR 就完全没有文字，定位必落默认位置 | **不要直接交付**。先按输出里的 pip 命令安装 rapidocr_onnxruntime 后重跑；装不上则告知用户"只能盖在默认右下角，请人工核对位置" |
| `❌ 输出路径与...路径相同，执行会覆盖源文件` | 输出路径撞了输入或公章路径 | 换一个输出路径重跑 |
| `智能定位成功（策略：明确盖章栏）` 或 `（策略：列对齐裸签章栏）` | 已自动定位到该角色盖章处 | 直接交付输出文件 |
| `策略：对侧对称(与他角色盖章栏同高,本角色列)` | 文档没有本角色盖章栏，按买卖双方章上下对齐习惯，盖在本角色关键字列、他角色盖章栏同高处 | 正常交付，可顺带说明盖在哪一行附近 |
| `已自动避让: (x,y) → (x2,y2)` | 默认落点会压到对方盖章栏/公司名，脚本已自动挪到最近合法位置 | 正常交付，可顺带说明已避开对方签章区 |
| `策略：公司名同行(无该角色盖章栏,建议人工确认)` | 文档没有该角色盖章栏，章盖在其公司名文字旁 | 交付时必须告知："该文档没有 X 方盖章栏，章已盖在其公司名旁，请确认位置" |
| `智能定位未成功，回退常规定位` 且有 `关键词定位成功` | 退化为关键词定位 | 交付时告知："未能智能识别角色，按关键词定位，请核对位置" |
| `⚠️ 关键词定位失败，使用默认位置` | 落到右下角兜底位置 | **不要直接交付**。告知用户位置不可靠；知道角色就加 `--role 角色名` 重试，OCR 失败就加 `--company "公司名"` 重试 |
| `公章公司名 OCR 失败` | 公章文字没识别出 | 人工看公章图片读出公司名 → `--company "公司名"` 重试；读不出就问用户 |
| `合同未提取到'角色: 公司名'信息` | 合同文本无签署方栏 | 读合同判断我方角色 → `--role 角色名` 重试；判断不了问用户 |
| `公章匹配到角色: X（Y）` 但 X 与用户公司不符 | 匹配错了 | 用 `--role` 明确指定正确角色重试 |

**第 3 步：交付话术（固定）**
- 输出为防编辑压平版：公章与页面融为一体，PDF 编辑软件无法单独选中/移动/删除公章（法律安全），文字仍可搜索复制
- 图片输入的输出是图片：章已融入图片像素，任何图片/PDF 编辑软件都无法单独选中或移除公章
- 用户需要可编辑版（仅内部核对）时：加 `--no-flatten` 重新生成，并提醒法律风险
- 表中标注"人工确认"的场景，交付必须附带确认提醒

## 智能定位工作原理

```
公章图片 → 红色像素定位圆心 → 极坐标展开（环形公司名拉直成横排）
        → 4个起始角分别识别+投票（多角度避免文字被展开缝切断）
        → 清洗出公司名
合同PDF → 逐页提取"角色: 公司名"签署方对（甲方/乙方/卖方/买方/供方/需方/…）
        → 与公章公司名模糊匹配（容忍 OCR 单字误差）
        → 定位合同中该角色"（盖章）"文字处，章盖在其右侧
```

任何一步失败只打印警告并**自动回退**常规定位（参考章对称 → 关键词 → 默认位置），
绝不阻塞盖章。智能定位依赖不可用时同样降级，盖章主流程不受影响。

## 参数说明

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `--side left|right` | 常规定位时放置在参考公章的左侧还是右侧 | `right` |
| `--rotate N` | 旋转角度（度），正值=逆时针（向左旋转），负值=顺时针 | `20` |
| `--offset-x N` | 水平微调位置，正值向右移动 | `0` |
| `--offset-y N` | 垂直微调位置，正值向下移动 | `0` |
| `--keywords A,B,C` | 常规定位的关键词，逗号分隔 | `签章,公章,盖章` |
| `--no-auto` | 关闭智能定位，回退常规定位 | 默认智能定位 |
| `--company "公司名"` | 手动指定公章公司名（OCR 不准时兜底） | 自动 OCR |
| `--role 角色名` | 手动指定盖到哪个角色（甲方/乙方/卖方/买方/…） | 自动匹配 |
| `--no-flatten` | 不压平，公章保留为独立图片对象（可被编辑软件修改，仅应急用） | 默认压平 |
| `--dpi N` | 压平渲染分辨率，越高越清晰、文件越大 | `300` |
| `--dry-run` | 只分析不生成文件，方便预览位置和尺寸 | - |

公章默认图片路径为 `默认公章图片.png`（脚本同目录下），如不指定公章图片则自动使用默认公章。

## 防编辑压平说明

压平后的盖章页 = **一张整页位图 + 隐形文字层**：

- **公章不可编辑**：整页视觉内容来自位图，公章是页面像素的一部分，不是独立图片对象，
  任何 PDF 编辑软件都无法把它单独选中、移动、抠走或删除
- **文字仍可用**：原文字以隐形方式（render_mode=3）重建，搜索、复制、阅读器打开
  显示效果与压平前一致
- **其余页不受影响**：只压平盖章那一页，其他页保持原样
- `--no-flatten` 会退回叠加方式（公章=独立图片对象，可被编辑软件选中移动），
  仅在需要拿到"可编辑半成品"时使用，正式交付一律用默认压平输出

## 核心原理

0. **输入转换（Excel/图片/扫描件 → 文本版 PDF）**：
   - Excel 工作簿（v1.2.0）：调用本机 Excel COM「另存为 PDF」（等同一人工操作）→
     文本版 PDF，直接复用原管线
   - 图片 → 规格化为 595pts 宽页面；扫描件 → 150dpi 渲染每页；整页 OCR
     （rapidocr 带 det 模式，按行识别）→ 以 render_mode=3 写入隐形文字层，
     生成"整页位图 + OCR 文字层"的规范化 PDF。
   之后所有定位/盖章/压平流程与文本版合同**完全共用同一管线**
0. **智能定位（默认第一步）**：OCR 识别公章公司名（极坐标展开环形文字）→ 匹配合同
   "角色: 公司名" → 定位该角色"（盖章）"文字处；失败自动回退以下常规流程
1. 扫描 PDF 检测已有公章（红色圆形印章），提取参考公章图片
2. 用红色检测裁剪参考公章的内容区域，计算内容在 PDF 中的实际视觉大小（pts）
3. **如果没有已有公章**，自动搜索关键词（如"签章"、"公章"），定位签名区域：
   - 在 PDF 中搜索包含关键词的文字
   - 过滤掉过宽的正文行（>200pts），只保留签名区短标签
   - 将距离相近的关键词聚类为同一文字块
   - 左侧优先，同侧优先选最后一页
   - 公章左侧对齐关键词文字块的右侧边缘
4. 对新公章图片：
   - **PNG（RGBA）**：直接用 alpha 通道裁剪，去除透明 padding
   - **JPG/JPEG（RGB）**：先用红色检测生成透明 alpha 通道，转为 RGBA 格式，再裁剪
5. 以参考公章内容区域的实际视觉大小为基准放置新公章，确保视觉大小一致
6. 支持旋转角度，模拟真实盖章效果
7. **压平防编辑**：将盖章页按 `--dpi`（默认 300）栅格化为整页位图，再以隐形方式
   （render_mode=3）重建原文字层，其余页原样保留——公章从此是页面像素的一部分，
   不再是可被编辑软件单独操作的独立图片对象

## 支持的图片格式

| 格式 | 处理方式 | 透明背景 |
|------|---------|---------|
| PNG（RGBA） | 直接用 alpha 通道裁剪 | ✅ 原生支持 |
| PNG（RGB） | 红色检测 → 转 RGBA → 裁剪 | ✅ 自动转换 |
| JPG/JPEG | 红色检测 → 转 RGBA → 裁剪 | ✅ 自动转换 |

## 示例

你的合同 PDF 已经有对方公章在左侧，要把你公司公章添加到右侧：
```bash
# 使用默认公章
python pdf_seal_stamper.py contract.pdf

# 或指定自定义公章（支持 PNG / JPG / JPEG）
python pdf_seal_stamper.py contract.pdf my_company_seal.png
python pdf_seal_stamper.py contract.pdf my_company_seal.jpg
```

调整旋转角度让公章看起来更自然：
```bash
# 逆时针旋转 15°
python pdf_seal_stamper.py contract.pdf --rotate 15

# 顺时针旋转 10°
python pdf_seal_stamper.py contract.pdf --rotate -10
```

先用 dry-run 预览再执行：
```bash
python pdf_seal_stamper.py contract.pdf --dry-run
```

自定义关键词定位（合同无参考公章时）：
```bash
# 使用默认关键词（签章、公章、盖章）
python pdf_seal_stamper.py contract.pdf

# 自定义关键词
python pdf_seal_stamper.py contract.pdf --keywords "签章,甲方盖章,乙方盖章"
```
