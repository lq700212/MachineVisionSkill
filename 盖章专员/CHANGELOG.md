## v1.1.1 (2026-09-02)

### 扫描件关键词定位三连修（实测"工伤保险待遇申领表"扫描件定位落空 → 命中"盖章"二字）

真实案例：3 页扫描件申领表，第 2 页底部"单位（盖章）/承诺人（签名）："签名栏，
旧版关键词定位必落空到默认右下角。排查发现根因是**三个独立缺陷叠加**，缺一修不可：

1. **OCR 检测器丢行**：rapidocr det 默认 `box_thresh=0.5`，签名栏整行检测框
   被丢弃，OCR 文字层根本没有这行 → `_lazy_full_ocr_engine()` 改
   `det_box_thresh=0.3` + `det_unclip_ratio=2.0` 提高召回（注意：新版
   rapidocr_onnxruntime 传任何 det_* 参数必须显式带 `det_model_path=None`，
   否则 KeyError: 'model_path'）
2. **文字层词宽失真**：`_insert_invisible_lines()` 按行高推字号，文字横向铺开
   =字号×字数，与 OCR 行框宽脱节（213pts 的行框被铺成 496pts）→ 写入前用
   `fitz.get_text_length` 把词宽缩放到与 OCR 行框一致，定位/搜索才反映真实版式
3. **正文行过滤阈值过紧**：`find_keyword_blocks()` 的 `max_word_width` 200pts
   把 213pts 的签名栏整行误当正文过滤 → 放宽到 300（正文贯穿行通常 ≥380pts，
   仍可有效区分）

### 骑压精对齐：章骑在"盖章"关键词上，而不是长行几何中心

长签署行（如"单位（盖章）/承诺人（签名）："）触发骑压时，旧版章中心骑整块
几何中心——实际盖在"承诺人"附近，偏了半个行宽。现在按字符均布估算关键词在
块内的位置（文字层词宽已校准，见上），章中心精对齐到命中的关键词（"盖章"）
二字处；找不到关键词明细（智能定位合成块）时退回块中心原行为。
`find_keyword_blocks` 的 block 新增 `kw_words` 命中词明细字段承载此能力。

### 验收

- 真实扫描件：关键词定位成功，章中心对准第 2 页"（盖章）"处（红像素中心实测
  (282.0, 603.1) vs 期望 (283.1, 606.0) pts）；压平防编辑通过（1 张整页位图）、
  文字层可搜索（"单位（盖章）"可搜到）

## v1.1.0 (2026-09-01)

### 三类输入统一支持：文本版 PDF / 扫描件 PDF / 图片（拍照件）

**设计核心：输入规范化，而非新写定位逻辑**。扫描件/图片先转换为"整页位图 +
OCR 隐形文字层"的规范化 PDF（与压平同一套 render_mode=3 技术），之后智能定位/
角色匹配/禁忌区避让/骑压/压平**零改动复用原管线**——所有已有策略、决策表、
防编辑能力对三类输入自动生效。

- **扫描件 PDF**：每页 get_text 不足 20 字符判定为无文本层 → 150dpi 渲染每页 →
  整页 OCR（rapidocr **带 det** 模式，按行识别；与公章 rec-only 是两种用途，
  不可混用）→ 逐行写入隐形文字层（整行一次 insert_text 保行结构，签署方正则
  "需方：A 供方：B"同行多对匹配依赖此）→ 输出 PDF 文字反而可搜索（增强）
- **图片输入**（png/jpg/jpeg/bmp/webp）：规格化为 595pts 宽页面（否则拍照大图
  按 1px=1pt 会让默认章宽占比严重失调）→ OCR 文字层 → 盖章压平后**渲染回与原图
  同分辨率、同格式的图片**（章融入像素，不可移除）；显式指定 .pdf 输出则给 PDF
- **OCR 依赖缺失诚实降级**：扫描件/图片没有 OCR 就完全没有文字 → 明确警告
  "定位必落默认位置，交付前必须人工核对"并给出 pip 安装命令，不阻塞盖章
- **输出覆盖防护**：输出路径与合同文件/公章图片路径相同时拒绝执行
  （测试事故曾把默认公章图片当输出覆盖销毁，git 恢复后固化此防线）
- 输出路径决策：图片输入未指定输出 → `原名_已盖章.原扩展名`；PDF 输入 →
  `原名_已盖章.pdf`（不变）

## v1.0.0 (2026-08-31)

> 本 skill 从未对外发布，此前的内部迭代记录已合并为本版本——首个正式版本。

### 核心能力

**智能定位（默认开启）：给一枚公章就知道盖哪**
- OCR 识别公章上的公司名：红色像素定位圆心 → 极坐标展开把环形公司名拉直成横排
  （顶行=外半径）→ 4 个起始角分别识别+投票（防展开缝切断文字）→ 红像素垂直投影
  裁主文字行 → rec-only 按字间隙分段识别拼接 → 清洗截断到组织后缀 + 质量评分选最优
- 自动匹配合同角色：逐页正则提取"角色: 公司名"签署方对（甲方/乙方/丙方/丁方/
  卖方/买方/供方/需方/出租方/承租方/发包方/承包方/委托方/受托方/招标人/投标人/
  借款人/贷款人/用人单位/劳动者），与公章公司名模糊匹配（互相包含或相似度 ≥0.55，
  容忍 OCR 单字误差）
- 定位该角色盖章处：搜索"该角色（盖章/公章）"文字块（带盖章字样避免误匹配抬头
  当事人栏），章左缘对齐文字块右缘
- 任何一步失败只警告并逐级回退常规定位（参考章对称 → 关键词 → 默认位置），绝不阻塞
- 人工兜底通道：`--company "公司名"`（OCR 不准）、`--role 角色名`（跳过 OCR 与匹配）、
  `--no-auto`（完全关闭智能定位）

**防编辑压平（默认开启）：公章与页面融为一体**
- 盖章页整页栅格化（默认 300dpi JPEG q92）+ 重建隐形文字层（render_mode=3，
  文字仍可搜索/复制，显示效果不变）
- 公章从此是页面像素的一部分，PDF 编辑软件（Acrobat/福昕/WPS 等）无法单独选中、
  移动、抠走、删除——杜绝法律风险
- `--no-flatten` 可退回叠加方式（公章=独立图片对象），仅限应急/内部核对
- 其余页原样保留，页数页序不变；`--dpi` 控制清晰度/体积

### 关键实现教训（详版见 AGENTS.md 历史事故档案）

- RapidOCR 的 det 检测器对公章大字彻底失灵，必须走 `use_text_det=False` 的 rec-only
- rec 输入宽度被压到 ~320px，整行十几字会丢字 → 必须分段；等宽硬切会把字切成两半
  （"光电"→"光中"）→ 必须在字间隙处下刀
- 极坐标展开轴向写反会整行镜像（顶行必须=外半径）
- pdfplumber/PyMuPDF 顶部原点 vs reportlab 底部原点，坐标系混算是定位第一大坑
- 叠加层公章是独立图片 XObject，可被编辑软件选中移动——这就是必须压平的根因
