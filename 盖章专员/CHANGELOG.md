# 版本更新记录

## v1.0.0 (2026-08-31)

> 本 skill 从未对外发布，此前的内部迭代记录已合并为本版本——首个正式版本。

### 核心能力

**智能定位（默认开启）：给一枚公章就知道盖哪**
- OCR 识别公章上的公司名：红色像素定位圆心 → 极坐标展开把环形公司名拉直成横排
  （顶行=外半径）→ 4 个起始角分别识别+投票（防展开缝切断文字）→ 红像素垂直投影
  裁主文字行 → rec-only 按字间隙分段识别拼接 → 清洗截断到组织后缀 + 质量评分选最优
- 自动匹配合同角色：逐页正则提取"角色: 公司名"签署方对（甲方/乙方/丙方/丁方/
  卖方/买方/供方/需方/出租方/承租方/发包方/承包方/委托方/受托方/招标人/投标人/
  借款人/贷款人/用人单位/劳动者），与公章公司名模糊匹配（互相包含或相似度 ≥0.55，
  容忍 OCR 单字误差）
- 定位该角色盖章处：搜索"该角色（盖章/公章）"文字块（带盖章字样避免误匹配抬头
  当事人栏），章左缘对齐文字块右缘
- 任何一步失败只警告并逐级回退常规定位（参考章对称 → 关键词 → 默认位置），绝不阻塞
- 人工兜底通道：`--company "公司名"`（OCR 不准）、`--role 角色名`（跳过 OCR 与匹配）、
  `--no-auto`（完全关闭智能定位）

**防编辑压平（默认开启）：公章与页面融为一体**
- 盖章页整页栅格化（默认 300dpi JPEG q92）+ 重建隐形文字层（render_mode=3，
  文字仍可搜索/复制，显示效果不变）
- 公章从此是页面像素的一部分，PDF 编辑软件（Acrobat/福昕/WPS 等）无法单独选中、
  移动、抠走、删除——杜绝法律风险
- `--no-flatten` 可退回叠加方式（公章=独立图片对象），仅限应急/内部核对
- 其余页原样保留，页数页序不变；`--dpi` 控制清晰度/体积

**常规定位三模式**（智能定位失败时的回退链）
- seal：检测到已有公章（近正方形 50~250pts 的图片），左右对称放置
- keyword：无公章时搜索"签章/公章/盖章"关键词（过滤正文长行+近邻聚类），章左缘
  对齐关键词文字块右缘
- default：全部失败的明示兜底（右下角），有警告输出，交付前需人工核对

**真实合同适配（5 份真实单据实测验收，测试固化于 run_test3_real.py，35/35 PASS）**
- 四级定位策略（find_role_stamp_block）：①明确盖章栏（"需方(签章)："——盖章/公章/
  签章 × 全半角括号全组合）②裸签章栏+角色列对齐（订购单"签章： 签章："式，排除
  其他角色盖章栏，绝不盖到对方栏）③**对侧对称**（本角色无盖章栏但有他角色盖章栏：
  章与他角色盖章栏同高、落在本角色关键字列——报价单卖方章盖"卖方开户行"行、与
  "买方签字/盖章"上下对齐，用户口述规则实测校准）④公司名同行兜底（输出带"建议
  人工确认"提示）
- **骑压式盖章**：签署文字块宽≥章宽 90% 时，章中心骑在文字块上（模拟真实盖章
  压字）——修复"需方(签章)：XX公司"长行外排把章推出文本区贴页边（购销合同实测
  用户指出）；另加页面边界保护（所有模式通用，越界自动收进并打印警告）
- 签署方提取适配真实合同：一行多对"角色：公司名"（字符级 negative-lookahead 截断）、
  角色带"名称/单位"修饰（"买方名称："）、空白公司名栏不误吞下一段、纯数字（电话/
  账号）不混入
- 每类真实单据的验收基线（角色/策略/章落点区域）固化为预期表，一条命令复判
- **落点禁忌区动态判断层**（build_forbidden_zones + adjust_avoid_forbidden）：
  现场计算"他角色盖章栏+他角色公司名"禁忌区，落点相交自动网格搜最近合法位——
  同模板不同布局的文档自适应兼容，不依赖逐例打补丁；扫描件（无文本层）自动降级
- 定位阈值全部相对页面尺寸（同高水平带=页高7%、列距=页宽35%），横版/异形页兼容

**弱模型等效固化（用户明令：每个功能点、每次改动都要考虑，无需用户提醒）**
- AGENTS.md 铁律9：判断机检化（脚本输出给出下一步动作）、流程照抄化（SKILL.md
  输出→动作决策表）、兜底提示→照做级、测试一条命令出 PASS/FAIL
- SKILL.md 新增「标准作业流程」：命令模板 + 7 种脚本输出对应的行动决策表 + 固定
  交付话术——弱模型照抄即可达到与强模型一致的作业质量

**尺寸精确匹配**：从 PDF 提取参考公章原图，红色检测裁出内容区域，按内容占比换算
实际视觉大小（pts）放置新章——不受图片透明 padding 影响

**公章图片通用处理**：PNG(RGBA/RGB)、JPG/JPEG 全支持；RGB 自动红色检测转透明
背景，避免白底遮挡合同文字；裁掉透明 padding 只留印章内容

**盖章效果**：默认逆时针旋转 20° 模拟真实盖章，`--rotate`/`--offset-x`/`--offset-y`
可调；`--dry-run` 只分析不生成

**依赖自动安装**：脚本启动自检，缺失依赖自动经阿里镜像源安装；核心依赖装不上才
退出并给手动命令；OCR 属可选依赖，装不上自动降级不影响盖章。新增第三方依赖必须
登记脚本顶部 `REQUIRED_DEPENDENCIES` / `OPTIONAL_DEPENDENCIES` 表

### 关键实现教训（详版见 AGENTS.md 历史事故档案）

- RapidOCR 的 det 检测器对公章大字彻底失灵，必须走 `use_text_det=False` 的 rec-only
- rec 输入宽度被压到 ~320px，整行十几字会丢字 → 必须分段；等宽硬切会把字切成两半
  （"光电"→"光中"）→ 必须在字间隙处下刀
- 极坐标展开轴向写反会整行镜像（顶行必须=外半径）
- pdfplumber/PyMuPDF 顶部原点 vs reportlab 底部原点，坐标系混算是定位第一大坑
- 叠加层公章是独立图片 XObject，可被编辑软件选中移动——这就是必须压平的根因
