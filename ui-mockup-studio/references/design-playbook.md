# 设计手册 —— 怎么把设计稿做得"干净整洁且可评审"

> 这份手册解决的不是"配色好不好看"，而是**为什么有些设计稿一看就土、一看就乱**，
> 以及怎么用固定套路规避。写页面前读一遍，能省掉三轮返工。

---

## 一、先看反面：为什么"长文档式设计稿"不好用

参考稿 `Docs/ui_redesign_pages_mockups.html` 是**长文档式**：从上到下一路滚动，
每节一个标题 + 一组截图式卡片 + 说明文字。

它有三个结构性问题（不是审美问题）：

1. **看图和看目录要来回滚**。用户想看"弹窗和页面什么关系"，得滚三千像素。
2. **"面面俱到"变成"堆得越多越乱"**。页面、弹窗、状态、规范混在一条时间线上，
   没有一个地方能同时看到全貌。
3. **没有可交互的跳转**。图上的按钮是画出来的，点了没反应，
   用户无法验证"这个入口通向哪一页"。

**升级思路 = 从"文档"变"工作台"**：

| 维度 | 长文档式 | 工作台式（本 skill） |
| --- | --- | --- |
| 浏览方式 | 纵向滚动 | 三栏固定：左目录 / 中舞台 / 右说明 |
| 全貌 | 无 | 总览视图：全部页面+弹窗缩略图同屏 |
| 跳转 | 文字描述 | 真按钮，点了真跳，另有自动生成的跳转图 |
| 多方案 | 复制多份，越写越长 | 一套 DOM + Token 切换，5 套实时对比 |
| 明暗 | 另开一节再画一遍 | 正交开关，任意方案随时切 |
| 交付评审 | 截图丢群里 | 单文件发给对方，双击就能玩 |

结论：**设计稿的"信息架构"和它设计的软件一样重要**。工作台本身就是一次示范。

## 二、"干净整洁"的 8 条硬指标（可逐条验收）

### 1. 一个页面只讲一件事

判断法：如果一屏里有两个"主操作按钮"抢焦点，就拆页或降级其中一个。
工业软件常见错误：主界面上同时放"开始运行""参数配置""导出报表"三个同权重按钮。

### 2. 视觉层级不超过 3 层

- L1 页面标题（`.app-title`）
- L2 区块标题（`.card-h b`）
- L3 正文/标签（`.tiny.muted`）

超过 3 层就会"每行都在喊"。**不要用字号+颜色+加粗三重叠加去强调同一件事**。

### 3. 颜色只用 3 个家族

主色（品牌/操作）+ 语义色（OK/WARN/NG）+ 中性色（背景/边框/文字）。
第 4 个颜色出现时先问：能不能用主色的透明度代替？

### 4. 对齐靠网格，不靠眼睛

- 间距只用 `--gap` / `--pad` 的倍数（4/8/12/16/20/24）。
- 卡片内边距统一 `var(--pad)`，不要这张 12px 那张 18px。
- 表单标签统一右对齐定宽（模板 `.formrow > label` 是 86px），
  这样一列输入框左边能对齐成一条竖线。

### 5. 边框要克制

- 能用**背景色差**分层就不要用边框。
- 一个容器最多一条 1px 边框；不要"卡片边框 + 表格边框 + 分隔线"三层叠。
- 表格只保留表头下边线 + 行间细线，**不要竖线**（竖线是"Excel 感"的来源）。

### 6. 状态用胶囊，不要整行染色

`<span class="st ok">OK</span>`。整行红底会让人以为整页报错。
数字型 KPI 可以用浅色底 + 彩色数字（`.kpi.ok .k-v`），比整块染色高级。

### 7. 留白是"呼吸"，不是"没画完"

- 页面四周 `var(--pad)`，区块之间 `var(--gap)`。
- 主内容区至少留 1 个"空白块"的余量：内容占 80%，留 20% 呼吸。
- 表格区如果只有 3 行数据，让卡片**撑满**剩余高度（`flex:1`），不要缩成一条。

### 8. 文字长度可控

- 标题 ≤ 12 字；按钮 ≤ 4 字（"导出 Excel"可以，"将当前结果导出为 Excel 文件"不行）。
- 表格列宽给足，宁可少一列也不要挤成两行。
- 长路径/长 IP 用等宽字体 + `text-overflow:ellipsis` + `title` 全文。

## 三、卡片设计原则（卡片式页面的成败全在这一节）

**一句话判据**：卡片是"装内容的容器"，不是"装饰框"。一张卡片上能读出的信息，
决定这个界面像专业软件还是像后台模板。

### 1. 三段结构，没有例外

```
┌──────────────────────────────┐
│ 图标  标题        状态/汇总  │  .card-h  卡头：说这张卡是什么
├──────────────────────────────┤
│                              │
│  卡身：只放读得懂的内容       │  卡身：直接写，不再多包一层
│                              │
├──────────────────────────────┤
│ 动作 / 汇总                  │  .card-f  卡脚：动作与汇总只放这里
└──────────────────────────────┘
```

- 卡头：20×20 图标块 + 12.5/700 标题 + 次要色副标题，右侧留给状态或关键数字。
- 卡身：**直接写内容**，禁止再套一层"内容框"（那是内嵌分区 `.card.inset` 的活）。
- 卡脚：负 margin 通栏贴底，底色 `panel2`，只放动作与汇总。
- **卡头卡脚在 flex 列里不许被压缩**（`flex:0 0 auto`）——内容一多，
  标题被压成一条缝是卡片体系最常见的塌方（Chrome 实测：`clientHeight` 只剩 16px）。

### 2. 按职责选变体，不按喜好选

| 职责 | 变体 | 判据 |
| --- | --- | --- |
| 页面主分区 | `.card` | 同页 2~4 张，多了拆页 |
| 回答"最要紧的那个数" | `.card.hero` | 一屏一张 |
| 最近 N 条 / 设备清单 | `.card.pad0` + `.card-h.band` + `.rows` | ≤10 行，再多上表格 |
| 故障 / 越限 | `.card.rail.ng` | 只染左缘与标题，不铺红底 |
| 当前工位 / 正在编辑 | `.card.top` | 一屏一张，多张等于没焦点 |
| 卡内分组 / 只读区 | `.card.inset` | 浅底、去描边、圆角小 4px |
| 密集小格 | `.tiles/.tile` | 一格一个对象，不放假长文本 |
| 设置页分组 | `.card.fold` | 组头常驻、组身折叠 |
| 压在内容上的浮层 | `.card.glass` | 普通分块禁用（模糊拖慢老工控机） |

列表卡的行要与卡头/卡脚**同一左缘**：行的水平内边距 = `--card-pad`、行高固定 30px。
缩进写小了（如 `padding:8px 2px`），整列文字会比标题内收一截，看着就是没对齐。

**同页最多同时出现 3 种卡片语言**：容器与指标同族算一种，告警算一种，
内嵌分区不算独立语言。再多就是"每个区块一套风格"，页面看着散。

### 3. 一卡一个语义色

左缘条 / 关键数字 / 徽标三者**只选一**。同一张卡里既有红条又有红标题又有红底，
等于告诉用户"这张卡全都是错误"，反而读不出重点。

### 4. 层次靠底色差与 1px 描边，不靠重投影

卡片三层底色：`--panel`（卡身）→ `--panel2`（卡头/卡脚）→ `--card-well`（内嵌分区）。
投影只留给浮层弹窗；一屏 72 张卡各带一层重阴影，叠起来必脏。

**浅色方案的描边必须比深色深**（`--card-line` 浅色 `#dbe0ea` vs 深色 `#26364f`）：
白卡漂在白底上，描边淡一点就完全看不出边界。

### 5. 状态六态（少一态就是没画完）

默认（描边 + 顶缘高光）/ 悬停（上移 1px + 边框提亮）/ 选中（主色边 + 3px 光晕）/
告警（左缘 3px 红条）/ 焦点（顶线 3px 渐变）/ 禁用（整体 55%）。

**选中态要能和状态同时读出来**：选中是"我在看它"，不是一种状态。
只换描边会和"老化中"的蓝色左条打架，正确做法是底色轻微染主色 + 实边外圈。

### 6. 卡片规范必须单独成一章

卡片式页面的 `spec` 视图里必须有「卡片规范」整行区块：
**解剖（真实 DOM）+ 参数表（实时读 Token）+ 状态矩阵 + 按职责的变体库**。
只在 CSS 里写一句 `.card{background;border;radius}`，等于没有卡片设计规范，
交接时落地的人只会照抄一个框。

## 四、页面骨架（工业软件/管理后台通用）

```
┌──────────────────────────────────────────────────────────┐
│ .app-bar   logo 标题  状态胶囊×N         料号 主操作 设置 │ 46px
├──────────┬───────────────────────────────────────────────┤
│ .app-nav │ .app-main                                     │
│ 侧栏     │  ┌─ 筛选卡（一行放完，主操作靠右）──────────┐ │
│ 150px    │  └──────────────────────────────────────────┘ │
│          │  ┌─ KPI 四宫格 ─────────────────────────────┐ │
│          │  └──────────────────────────────────────────┘ │
│          │  ┌─ 主内容（表格/磁贴/表单）flex:1 ─────────┐ │
│          │  │                                          │ │
│          │  └──────────────────────────────────────────┘ │
├──────────┴───────────────────────────────────────────────┤
│ .app-foot  运行中 · 节拍 · 今日 OK/NG         版本号      │ 30px
└──────────────────────────────────────────────────────────┘
```

变体：

- **主界面（监控型）**：无筛选卡，主内容是 `2×2` 相机磁贴 + 底部固定日志（132px）。
- **表格型子页**：筛选卡 + KPI + 表格（flex:1）+ 分页条。
- **配置型子页**：左设备树（210px）+ 右参数表（两列 `1fr 1fr`）+ 底部固定保存。
- **详情型子页**：顶部返回 + 摘要卡 + 下方多 Tab 内容。

**子页面必须有的三件套**：返回入口（`data-go="main"`）、页面标题（带英文副标题）、
主操作按钮（靠右）。缺任何一个，用户会觉得"点进来了出不去"。

### 5.3 9 基因红线（check 脚本 C23~C26 自动核验）

```
色相家族  5 套主色跨 >= 3 个家族、彩色两两色相距离 >= 30°、至少 1 套暖色或中性（C23）
明暗默认  深浅分布别全站同侧
圆角形态  直角(3px) ~ 胶囊(99px) 至少 3 档
密度留白  gap 9 ~ 22 至少 3 档
质感手法  描边高光/细线/大投影/平面硬边/发光 至少 3 种
字体气质  --font 至少 2 种（C25）
强调手法  渐变/发光/细线/色块，不要 5 套同款
壳层构图  sidebar/tabs/dock/cmdbar/iconrail 至少 3 种（C26）
动效性格  --dur-page .16s(干脆) ~ .42s(柔和) 至少 2 档
```

**任意两套方案，10 个基因 Token（primary/primary2/accent/radius/btnradius/
gap/pad/fs/font/shell）至少 5 项不同**（C24）。只换主色的两套方案不算两套。

### 5.4 壳形态库（同一 DOM，5 种构图）

| --shell | 构图 | 实现要点 |
| --- | --- | --- |
| sidebar | 左侧栏后台（默认） | `.app-nav` 150px 垂直，不做覆写 |
| tabs | 顶栏 Tab | `.app-body` 转 column，nav 横排、下划线式 active |
| dock | 底部 Dock | nav `order:2` 沉底、胶囊悬浮、主区全宽 |
| cmdbar | 顶部命令条 | nav 横排紧凑、虚线分隔、等宽小字号 |
| iconrail | 图标窄栏 | nav 56px，文字 `font-size:0` 只留图标 |

门面页（≤3 页）需要更强的构图差异时用 `data-layout` 分叉（见铁律 2 与
`mockup-spec.md` 的 data-layout 片段）；常规子页/弹窗不分叉。

**明暗正交**：每套方案有默认明暗；顶栏可任意切。
写页面时**只准用 Token**，这样所有组合都不会破相。

## 六、动效参数（结构照抄，性格随方案）

关键帧结构（`sPageIn`/`sDlgIn`）全稿一套（C13 核验）；**时长与缓动走
`--dur-page`/`--dur-dlg`/`--ease-page`/`--ease-dlg` Token，随方案基因变**——
出厂 5 套已各配性格（D 终端 .16s 干脆、C 日落 .42s 柔和），重校准时一起调。
下表是结构与出厂默认值：

| 场景 | 出厂时长 | 出厂缓动 | 位移 |
| --- | --- | --- | --- |
| 页面切换 | `--dur-page` .34s | `--ease-page` `cubic-bezier(.22,.9,.28,1)` | 上移 12px + scale .994 |
| 弹窗进场 | `--dur-dlg` .26s | `--ease-dlg` `cubic-bezier(.2,.9,.25,1.08)`（轻微过冲） | 上移 14px + scale .96 |
| 遮罩淡入 | 180ms | ease | 无 |
| 列表行入场 | 220ms | ease-out | 左移 7px |
| 按钮 hover | 160ms | ease | 亮度 1.1 + 阴影 |
| 按钮 active | — | — | 下移 1px |
| 加载旋转 | 800ms 线性循环 | linear | — |
| 骨架微光 | 1200ms 循环 | linear | 背景位置 |

红线：

- **不要做"整页飞入/翻转"**。工业软件的用户一天点 500 次，动效超过 400ms 就是折磨。
- 动效必须受**总开关**（`html[data-motion="off"]`）与 `prefers-reduced-motion` 双重控制。
- 弹窗**不要**从屏幕边缘滑入，用户会以为卡了。
- 不要给表格每一行都做循环动画（几十行动起来像扫描仪故障）。

## 七、常见"破相"清单（自查用）

| 症状 | 根因 | 修法 |
| --- | --- | --- |
| 换方案后有块地方还是蓝色 | 写死了色值 | 全局搜 `#` 和 `rgb(`，页面内清零 |
| 浅色下卡片还是黑的 | 卡片写死 `background:#0d131c` | 改 `var(--panel)` |
| 缩略图里页面缺内容 | 克隆页面时 `state-block` 还停在 `display:none` | 克隆后按 `data-for="default"` 恢复 |
| 弹窗打开后页面还是旧的 | 没按 `data-parent` 切背景页 | `openDialog` 里先 `switchPage(parent)` |
| 弹窗被撑成一条 | 复用了 `.dlg` 类名给别的元素 | 非弹窗外框一律用 `.is-dlg` |
| 跳转图糊成一团 | 画了返回/关闭等反向边 | 只画前进边；弹窗挂父页同列 |
| 页面比窗口大、要横向滚 | 分辨率写太大（如 1920×1080） | 统一 1440×900，靠 `zoom` 缩放 |
| 表格数字参差 | 数字列没右对齐、没用等宽字体 | `class="num"`（模板已带） |
| 卡片标题被压成一条缝 | flex 列里卡头参与压缩 | `.card-h`/`.card-f` 加 `flex:0 0 auto` |

## 八、从设计稿到落地的注意点（评审通过后）

1. **先定 Token 再写代码**：把 `spec` 视图里的 `--primary/--radius/--gap/--fs`
   抄成目标技术栈的常量（WinForms 用一个 `Theme` 静态类；Web 用 `:root`）。
2. **布局按 1440×900 设计，按 1366×768 验收**：所有卡片/表格都要在
   `1366` 宽、`768` 高下不溢出（工业现场笔记本常见）。
3. **表格列宽写死比例，不要写死像素**：`DataGridView` 用 `FillWeight`。
4. **动效降级**：WinForms 没有 CSS 动画，用 `Timer` 做 120~200ms 的透明度/位移渐变；
   做不了就**直接去掉动画**，不要用"弹一下"的粗糙实现。
5. **状态色统一**：设计稿里的 `--ok/--warn/--ng` 必须映射成同一套 GDI 颜色常量，
   否则"设计稿绿"和"程序绿"不是一个绿，客户一眼看出来。
6. **弹窗宽度**：设计稿 560px，落地时按 96 DPI 换算；高 DPI 下要用
   `AutoScaleMode.Dpi`，不要写死像素位置。
7. **交付时附"未实现项"清单**：设计稿里画了但本期不做的（导出 PDF、动画、图表），
   必须明说，避免验收时被当成缺陷。
