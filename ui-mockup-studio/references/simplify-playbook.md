# 简化与易上手手册（原 ui-simplify 并入）

> 来源：2026-11-10 用户对同一程序连续四个配置/表单窗（登录、工单、扫码枪配置、
> 过账配置、用户管理）逐个拍板"太复杂、简化"后沉淀的方法论；2026-11-16 并入
> `ui-mockup-studio`，并补上 WinForms 坑位、信息预算、炫点配额与"易上手"判定。
>
> **默认执行，不等用户提醒**。用户说"太复杂/简化/看着乱/能合并就合并/简单好上手/
> 配置项太多/按钮太多/降低学习成本"，就是全套走一遍。

---

## 一、核心理念：界面只放"要用户做的决定"

信息分三层，逐层有去处：

| 层 | 内容 | 去处 |
| --- | --- | --- |
| 决策字段 | 用户要填、要选、要点的 | **上界面** |
| 语境说明 | 字段键名、API/寄存器号、格式约束、现场口径、"为什么" | **ToolTip**（关键字段可一行小字） |
| 操作结果与全局口径 | 保存即生效、失败怎么办、红线底线 | **顶部一行提示条**，细节进 ToolTip |

判断口诀：**这段文字删掉后，用户第一次用会不会做错？**
会 → 留（收缩成一行或 ToolTip）；不会 → 删。

配套口诀（新增）：
**这个控件删掉后，用户还能不能完成任务？** 能 → 删或折叠；不能 → 留。

## 二、信息预算（硬指标，超了就返工）

一个"干净"的页面不是靠审美，是靠**配额**。默认按这张表执行：

| 对象 | 预算 | 超了怎么办 |
| --- | --- | --- |
| 一屏主操作按钮 | **1 个** | 其余降级为次操作（ghost）或收进"更多" |
| 一屏按钮总数（不含表格行内） | **≤ 10 个**（硬上限 12） | 合并同链操作、低频收进菜单/高级 |
| 顶栏常驻可点元素 | **≤ 4 个**（含设置） | 与侧栏重复的删掉；低频配置移入设置页 |
| 侧栏导航项 | **≤ 7 项** | 合并同域页面（相机+通讯→设备通讯）；分组折叠 |
| 一屏开关（Toggle/Switch） | **≤ 3 个**（硬上限 5） | 互斥开关改单选/下拉；默认值合理的藏进高级 |
| 一个页签首屏字段 | **≤ 8 个** | 分"基础/高级"，高级默认折叠 |
| 一行筛选条件 | **≤ 4 个控件** | 合并同源（IP:端口、日期范围）、低频进"更多筛选" |
| 卡片头部操作 | **≤ 1 个** | 其余收进卡片右键/行内"⋯" |
| 表格行操作 | **≤ 1 个"⋯"** | 展开菜单放编辑/删除/复制 |
| 页面标题 | **≤ 12 字** | 副标题用英文/模块名，不写长句 |
| 按钮文案 | **≤ 4 字** | "导出 Excel"可，"将当前结果导出为 Excel"不行 |
| 表头 | **≤ 6 字** | 超了改短名 + ToolTip 全称 |
| 页面说明（data-desc） | **≤ 60 字** | 一句话说清"给谁、干什么" |
| 单条设计要点（data-points） | **≤ 40 字** | 一条只讲一个决策 |
| 空态文案 | **≤ 20 字 + 1 个动作** | "没有记录 · 换个日期再查"，不要写三段 |

> `check_mockup.py` 的 W5/W6/W7 会自动盯按钮、开关与说明长度；
> 超了是 WARN，但交付前应当修到 PASS（或写明为什么必须超）。

**预算不是死的**：安全/合规/多客户差异/高频生产参数确实需要细分时，
**允许超，但必须在右栏"设计要点"里写一句为什么**（例："心跳三项必须独立可调，
因为不同 PLC 的停跳判据不同"）。

## 三、合并整合的五个判定（按顺序问）

1. **两个操作是否总是一起用？** → 合并成一个（"保存并测试"）。
2. **两个配置是否描述同一件事？** → 合并成一行/一组（IP : 端口、机架/槽位、
   心跳地址 · 周期）。
3. **这个页面是否是另一个页面的低频子集？** → 收进设置/抽屉/二级弹窗，
   不占一级导航。
4. **这个开关是否只影响本页？** → 改成页内的模式选择（下拉/分段），
   不要用"开关 + 保存"。
5. **这个按钮是否与侧栏/顶栏已有入口重复？** → 删掉重复的那个。

补充规则：

- **能自动推导的不让用户填**：选品牌→端口默认 102；选相机型号→分辨率只读；
  当前料号→报表默认筛选，不显示下拉。
- **有合理默认值的字段不要空着**：空下拉 = 逼用户思考。
- **互斥两态用 Radio / 分段**，不要"勾选框 + 长文案"。
- **危险操作不与常用操作并排**：删除放"⋯"里，且二次确认。

## 四、十条手法（逐条照抄）

1. **标签短化**：去掉括号键名 `(RC_NO)/(PortName)/(MAC_NO)`、去长括号注记
   （"（现场现行）""（勾选后可点下方上传按钮）"）。键名/口径/约束挪进 ToolTip；
   标签保持 2~5 字纯名词。英文枚举值同理：下拉只留中文短词。
2. **说明墙撤下**：右列/底部的"接线步骤①②③④、生效口径•••••"整段删除——
   浓缩成顶部一行提示条，细节分摊进**相关字段**的 ToolTip。
   **永远不要建"说明书列/说明卡"**——那是把文档当 UI 塞。
3. **合并同行**：同一动作链的控件收一行——使能勾选+触发按钮同行、
   数值框+清零钮同行、重置+删除同行。散碎分组能合就合（四组 → 两张卡）。
4. **低频折叠**：不常动的参数收进 Expander（缺省折叠），标题写清缺省语义——
   "串口参数（一般用默认）""静态参数（留空=用系统记忆）"。常用字段绝不折叠。
5. **互斥方式用 Radio**：两态互斥（TCP/串口）用两只 RadioButton，
   不用"勾选框+长文案"。WPF 绑定红线见第六节。
6. **删冗余**：与窗标题重复的组标题、与顶部权限条重复的字段级说明、
   随版本失准的过时文案——发现即删，不留过渡注释。
7. **窗形收敛**：表单/配置窗优先单列或两列**窄窗**（560~720），
   高度自适应 + MaxHeight（~780）兜底滚动 + 禁止随意拉伸
   （WPF：`SizeToContent="Height"` + `MaxHeight` + `NoResize` + `ResizeBorderThickness="0"`）；
   含列表（DataGrid/ListBox）的窗才用固定高。撤掉说明列后收窗宽，别留真空区。
8. **对齐与间距**：
   - 同窗多个输入 Grid 的标签列**统一固定宽**（如 86 / 60），
     各 Grid 独立 Auto 列按各自标签字数算宽，必错位；
   - 行间距 8~12px 呼吸；勾选行与按钮行**禁止零间距贴死**；
   - 同窗同类按钮统一尺寸（主钮 128×32、次钮 96×32、行内小钮 88~96×28）。
9. **语义零变化**：简化只动"文字与排布"——字段集合、ini/配置键名、校验规则、
   落盘口径、门禁权限一律不动。改前先列**外部契约清单**（MES 报文字段、
   寄存器语义、配置键名）；契约名称进 ToolTip 保留可查，绝不为省事删功能。
10. **测试与文案断言先查**：改标签/选项/按钮文案前先 grep 测试断言，
    有锁文案的用例同步更新；VM 属性无消费者后随视图删除一并删（不留死代码）。

## 五、易上手：新用户 3 秒知道下一步点哪

### 5.1 三条判定（拿给没见过的同事看，做不到就改）

1. **3 秒测试**：打开页面 3 秒内，视线能不能落到"主操作"上？
   （看颜色/位置/大小是否形成唯一焦点）
2. **三步测试**：完成最高频任务，能不能在 3 步内完成且不需要读说明？
3. **闭眼测试**：把页面上的说明文字全遮住，功能还能不能用？
   （能 → 说明文字本来就该进 ToolTip）

### 5.2 具体手法

- **主操作唯一**：每屏只有一个实心主色按钮；其余是 ghost 或图标。
- **动线可预期**：主内容在左上→右下（F 型）；主操作在右上或右下（固定位置，
  换页不跳）。不要这页右上、那页左下。
- **渐进披露**：高级参数默认折叠；低频功能放二级；危险操作放"⋯"。
  **折叠不是隐藏功能**——标题要写清里面有什么（"高级参数（机架/槽位、重连）"）。
- **陌生概念给一行灰字**：首次出现的关键概念（"停跳判据""覆盖根目录"）
  在字段下方给一行 ≤20 字解释，不写段落。
- **空态要有出路**：空表格不只写"暂无数据"，给"换个日期/清空筛选/新建一条"。
- **默认值可用**：新用户不改任何参数也能跑通主流程；默认值要写出来（不要空）。
- **图标必须带 ToolTip**：图标按钮无 title = 猜谜。`check_mockup.py` W8 会查。
- **危险操作可撤销或二次确认**：不可撤销的（删除、覆盖、停机）必须确认弹窗，
  确认按钮用红色且写清后果（"删除 3 条记录，不可恢复"）。
- **不要用"隐藏"表达"不可用"**：置灰只读 + ToolTip 说明原因，比消失更好懂
  （用户会以为功能丢了）。

## 六、炫点配额：该炫的地方炫，不该炫的地方克制

"简洁"不等于"丑"。但**一屏只允许一个炫点 C 位**，其余全部克制。

### 6.1 三个安全区（可以炫）

| 区域 | 可用的炫法 | 例子 |
| --- | --- | --- |
| 头部/品牌区 | 渐变标题栏、细光效、图标徽标 | 弹窗标题 `--titlegrad`、logo 渐变 |
| 数据可视化 | KPI 大数字、进度环、磁贴、图像区扫描光带 | 相机磁贴扫描线、良率进度条 |
| 状态反馈 | 发光状态点、微动效、数值变化闪一下 | `--okglow`、行入场 220ms |

### 6.2 三个禁区（禁止炫）

| 区域 | 为什么 | 正确做法 |
| --- | --- | --- |
| 表单/输入区 | 干扰填写、显得不专业 | 纯色输入框 + 1px 边框 + focus 主色描边 |
| 表格/数据区 | 影响扫读、降低密度 | 交替行底色 + hover 高亮，不加渐变/阴影 |
| 正文说明 | 抢注意力 | 灰字 + 行高 1.7，不加粗不加色 |

### 6.3 炫的纪律

- **动效 ≤ 400ms**，循环动画只给"正在运行"的视觉反馈（扫描线、加载环），
  且必须能被"动效总闸"关掉。
- **发光只用状态色**（OK/WARN/NG），不要给普通元素加彩色光晕。
- **渐变只用于"面"**（按钮底、标题栏、徽标），不用于文字主体、不用于表格。
- **一屏最多 1 个循环动画**；多块磁贴错峰（delay），不要同步闪。
- **炫点不能承载信息**：关掉动效/去掉渐变后，信息必须仍然完整可读。

> 模板里的示范：主界面相机磁贴的扫描光带（4.2s、主色 13% 透明度、四块错峰）
> 是唯一循环炫点；其余全部走静态 Token。这就是"该炫的炫，不该炫的闭嘴"。

## 七、WPF 坑位（血泪清单，改前对照）

- **触发器死区**：Visibility 等要被 DataTrigger 切换的属性，缺省值必须写 Style Setter——
  写在元素标签上是本地值，优先级高于触发器，触发器永远不生效。互斥双面板：
  一个缺省 `Visible`、一个缺省 `Collapsed`，都走 Setter。
- **独立 Grid 的 Auto 列互不对齐**（见手法 8）——固定宽最稳，`SharedSizeGroup` 次之
  （模式切换时列宽会跳）。
- **RadioButton 反向绑定互踢**：同组两钮只让**一只**双向绑 bool，另一只 `Mode=OneWay`
  + 取反转换器只做显示——两只都双向取反时，点击一只会先触发另一只的自动取消
  ConvertBack 写回错值，回写链必须唯一。
- **Expander 折叠内容绑定仍有效**（值照常 Sync/Flush）——低频参数收进去安全，
  不是"看不见就不保存"。
- **VM 清空属性会同步清字段**：成功路径要"清输入框 + 把值转存别处"时，
  先存局部变量再清（`var v = _field; Field = "";` 再用 `v`）。
- **PasswordBox/特殊控件不可绑定**：沿用事件转交 + 回写（"值不同才走"防互踢）。
- **键盘链按面板模式分发**：互斥面板各自定义回车跳框顺序与 Esc 语义。
- **换肤必须 DynamicResource**：`StaticResource` 在运行时切换主题不刷新
  （颜色永远停在启动那一刻）。

## 八、WinForms 坑位（本 skill 新增，同为血泪）

- **高 DPI 三要素缺一必错位**：`AutoScaleMode = Dpi` + `AutoScaleDimensions`
  （与设计时 DPI 一致，96 时 96F,96F）+ 容器/控件不用绝对坐标堆叠。
  纯代码建窗体这三样都要手写，不会自动生成。
- **绝对坐标 + 高 DPI = 逐像素偏移**：用 `TableLayoutPanel` / `FlowLayoutPanel`
  / `Dock` 布局；必须定位时按比例算，不写死 `Location`。
- **自绘圆角的四角脏边**：`Region` 是硬裁剪（不抗锯齿），四角必有锯齿/脏边。
  根治：自绘背景（`GraphicsPath` + `AntiAlias` + 半像素补偿）且**不设 Region**，
  或让父容器同色把角"藏"掉；只在必要时用 Region 兜底。
- **自绘控件必须双缓冲**：`SetStyle(ControlStyles.OptimizedDoubleBuffer |
  AllPaintingInWmPaint | UserPaint, true)`，否则滚动/动画闪烁。
- **DataGridView**：开 `DoubleBuffered` 要走反射（protected 属性）；
  列宽用 `FillWeight` 不写死像素；`CellFormatting` 里不要每次 new Brush/Font
  （缓存成字段），否则千行表格滚动掉帧。
- **字体换算**：CSS 13px ≈ 9.75pt（px × 0.75）；微软雅黑 UI 9pt 在 96DPI ≈ 12px。
  设计稿字号直接乘 0.75 落地，不要凭感觉调。
- **动画用 Timer**：间隔 ≥ 30ms；只 `Invalidate()` 变化区域，不要整窗重绘；
  动画期间 `SuspendLayout` 无效（那是布局不是绘制）。
- **换肤统一入口**：递归遍历控件 + 自绘控件实现 `IThemeAware.ApplyTheme()`；
  不要在每次 `Paint` 里读 ini/配置。
- **无边框窗体的拖动/圆角**：需要 `WndProc` 处理 `WM_NCHITTEST`；圆角同样走
  "自绘 + 不设 Region"策略。
- **弹窗**：`ShowDialog()` 前设 `StartPosition = CenterParent`；
  高 DPI 下确认 `AutoScaleMode` 与主窗一致，否则弹窗大小与设计稿差一圈。

## 九、目检纪律（构建过 ≠ 好看）

1. **UI 改完必须截图目检**：有截图 harness 就跑，没有就起真窗截图。
   只看"编译 0 错误、测试全绿"不算完——测试测不出"按钮叠在勾选框上"。
2. **放大逐项核对五件事**：
   ① 所有输入框左缘是否一条线；
   ② 行与行有没有贴死/叠压；
   ③ 标签与框的间距是否统一；
   ④ 撤掉内容后有没有真空区/失衡列；
   ⑤ 提示条、按钮、窗宽比例是否协调。
3. **同类问题一次改净**：用户指出一处对齐/重叠，全窗（乃至同批窗）扫一遍
   同模式的问题一起修——别挤牙膏。
4. **删掉的文案要有去处**（ToolTip/提示条），现场血泪坑提示必须保留在 ToolTip。
5. **多分辨率各看一遍**：1366×768（现场笔记本）与 1920×1080（办公室）
   都要不溢出、不挤压。

## 十、执行流程（简化现有界面）

1. **调研**：读窗 XAML/cs + VM + 关联测试断言；列出现有字段/文案/分组清单；
   标出**外部契约**（键名、报文字段、寄存器语义）。
2. **方案**：按三层模型列**去向表**——界面留什么、ToolTip 收什么、删什么、
   合并什么、折叠什么；对照第二节预算表算一遍超标项。
3. **实施**：改界面（+必要的 VM 文案/属性清理）；遵守第七/八节坑位清单。
4. **验证**：构建 0 警告 + 全量测试 → 截图目检五件事 → 有测试锁文案的同步更新。
5. **沉淀**：改动与口径变化记 CHANGELOG；项目 AGENTS/README 的 UI 语义段同步。

### 与设计稿模式的衔接

- **只简化、不换视觉** → 直接按本手册改代码，改完截图目检。
- **既简化、又要换视觉/给客户选** → 先按本手册做信息架构减法（确定页面/弹窗/
  字段清单），再用 `ui-mockup-studio` 出 4-5 套设计稿。顺序不能反：
  先出稿再减法 = 五套稿一起返工。
- **简化后想证明"确实更好"** → 设计稿里保留一个"改造前"页面做对照
  （同一 `data-group`，标题加"（现状）"），评审时左右切着看。
