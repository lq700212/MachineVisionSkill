# ui-simplify：上位机界面简化与目检标准

来源：2026-11-10 用户对同一程序连续四个配置/表单窗（登录、工单、扫码枪配置、过账配置、用户管理）逐个拍板"太复杂、简化"后沉淀的方法论。用户明确要求：**以后做界面默认按本标准执行，不要等用户提醒**。

## 核心理念：界面只放"要用户做的决定"

信息分三层，逐层有去处：

| 层 | 内容 | 去处 |
| --- | --- | --- |
| 决策字段 | 用户要填、要选、要点的 | **上界面** |
| 语境说明 | 字段键名、API/寄存器号、格式约束、现场口径、"为什么" | **ToolTip**（关键字段可一行小字） |
| 操作结果与全局口径 | 保存即生效、失败怎么办、红线底线 | **顶部一行提示条**，细节进 ToolTip |

判断口诀：**这段文字删掉后，用户第一次用会不会做错？** 会 → 留（收缩成一行或 ToolTip）；不会 → 删。

## 十条手法（逐条照抄）

1. **标签短化**：去掉括号键名 `(RC_NO)/(PortName)/(MAC_NO)`、去长括号注记（如"（现场现行）""（勾选后可点下方上传按钮）""（免验原密码）"）。键名/口径/约束全部挪进 ToolTip；标签保持 2~5 字纯名词（"途程单号""启用过账""重置密码"）。英文枚举值同理：下拉选项只留中文短词（"秒"而非"Seconds（秒，老项目口径）"）。
2. **说明墙撤下**：右列/底部的"接线步骤①②③④、生效口径•••••、口径说明"整段删除——浓缩成顶部一行提示条（如"保存即生效，不需要重启程序"），细节分摊进**相关字段**的 ToolTip（接线说明放 IP 字段、重连口径放提示条 ToolTip）。**永远不要建"说明书列/说明卡"**——那是把文档当 UI 塞。
3. **合并同行**：同一动作链的控件收一行——使能勾选+触发按钮同行、数值框+清零钮同行、重置+删除两个按钮同行。散碎的分组标题能合就合（四个组 → 两张卡："生产信息"+"制程与上传"）。
4. **低频折叠**：不常动的参数收进 Expander（缺省折叠），标题写清缺省语义——"串口参数（一般用默认）""静态参数（留空=用系统记忆）"。常用字段绝不折叠。
5. **互斥方式用 Radio**：两态互斥（TCP/串口）用两只 RadioButton，不用"勾选框+长文案"。WPF 绑定红线见下节。
6. **删冗余**：与窗标题重复的组标题（窗叫"工单信息"、卡内再挂"工单信息"）、与顶部权限条重复的字段级权限说明、随版本改版失准的过时口径文案（如旧"LEVEL.3"）——发现即删，不留过渡注释。
7. **窗形收敛**：表单/配置窗优先单列或两列**窄窗**（宽 560~720），`SizeToContent=Height` + `MaxHeight`（~780）兜底滚动 + `NoResize` + `ResizeBorderThickness=0`；含列表（DataGrid/ListBox）的窗才用固定高。撤掉说明列后右列变空 → 收窗宽，别留真空区。
8. **对齐与间距**：
   - 同窗多个输入 Grid 的标签列**统一固定宽**（如 60）——各 Grid 独立 `Auto` 列按各自标签字数算宽，必错位（"密码"2 字 vs"用户名"3 字时框左缘分叉）；
   - 行间距 8~12px 呼吸；勾选行与按钮行**禁止零间距贴死**（视觉即"重叠"）；
   - 同窗同类按钮统一尺寸（主钮 128×32、次钮 96×32、行内小钮 88~96×28）。
9. **语义零变化**：简化只动"文字与排布"——字段集合、ini/配置键名、校验规则、落盘口径、门禁权限一律不动。改前先列清单：哪些是外部契约（MES 报文字段、寄存器语义、配置键名），契约**名称进 ToolTip 保留可查**，但绝不为省事删功能或改口径。历史坑注释（如"此处纵排防溢出"）理解后再动，防回退。
10. **测试与文案断言先查**：改标签/选项/按钮文案前先 grep 测试断言，有锁文案的用例同步更新；VM 属性无消费者后随视图删除一并删（不留死代码）。

## WPF 坑位（血泪清单，改前对照）

- **触发器死区**：Visibility 等要被 DataTrigger 切换的属性，缺省值必须写 Style Setter——写在元素标签上是本地值，优先级高于触发器，触发器永远不生效。互斥双面板：一个缺省 `Visible`、一个缺省 `Collapsed`，都走 Setter。
- **独立 Grid 的 Auto 列互不对齐**（见手法 8）——固定宽最稳，`SharedSizeGroup` 次之（模式切换时列宽会跳）。
- **RadioButton 反向绑定互踢**：同组两钮只让**一只**双向绑 bool，另一只 `Mode=OneWay` + 取反转换器只做显示——两只都双向取反时，点击一只会先触发另一只的自动取消 ConvertBack 写回错值，回写链必须唯一。
- **Expander 折叠内容绑定仍有效**（值照常 Sync/Flush）——低频参数收进去安全，不是"看不见就不保存"。
- **VM 清空属性会同步清字段**：成功路径要"清输入框 + 把值转存别处"时，先存局部变量再清（`var v = _field; Field = "";` 再用 `v`），否则转存的是已清空的值。
- **PasswordBox/特殊控件不可绑定**：沿用事件转交 + 回写（"值不同才走"防互踢）的既有接线模式，新框各 Wire 一份。
- **键盘链按面板模式分发**：互斥面板各自定义回车跳框顺序与 Esc 语义（子面板 Esc=返回上级，主面板 Esc=关窗）。

## 目检纪律（构建过 ≠ 好看，用户拍板"目检放到合适好看的位置"）

1. **UI 改完必须截图目检**：WPF 项目有截图 harness 就跑（如一键 build+截图脚本），没有就起真窗截图。只看"编译 0 错误、测试全绿"不算完——测试测不出"按钮叠在勾选框上"。
2. **放大逐项核对五件事**：① 所有输入框左缘是否一条线；② 行与行有没有贴死/叠压；③ 标签与框的间距是否统一；④ 撤掉内容后有没有真空区/失衡列；⑤ 提示条、按钮、窗宽比例是否协调。
3. **同类问题一次改净**：用户指出一处对齐/重叠，全窗（乃至同批窗）扫一遍同模式的问题一起修——别挤牙膏。
4. **删掉的文案要有去处**（ToolTip/提示条），别把排障信息直接丢掉；现场血泪坑提示（如"勿把 A 地址当 B 地址填"）必须保留在 ToolTip。

## 执行流程

1. **调研**：读窗 XAML + VM + 关联测试断言；列出现有字段/文案/分组清单。
2. **方案**：按三层模型列去向表——界面留什么、ToolTip 收什么、删什么、合并什么；确认外部契约清单。
3. **实施**：改 XAML（+必要的 VM 文案/属性清理）；遵守框架坑位清单。
4. **验证**：构建 0 警告 + 全量测试 → 截图目检五件事 → 有测试锁文案的同步更新。
5. **沉淀**：改动与口径变化记 CHANGELOG；项目 AGENTS/README 的 UI 语义段同步。
