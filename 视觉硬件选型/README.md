# 视觉硬件选型技能

机器视觉检测方案自动化选型与PPT生成系统。

## ⚠️ 核心原则：参数必须有明确来源

**绝对不能猜测任何参数！**

| 参数 | 正确来源 | 错误做法 |
|------|----------|----------|
| 精度/公差 | 用户输入/资料提取 | 用默认值猜测 |
| 工件尺寸/视野 | 用户输入/资料提取 | 用默认值猜测 |
| 镜头倍率 | 数据库/用户确认 | 从型号名称推断 |

**错误示例：**
- ❌ 看到型号"DTCM110-64H-AL"中的"64"就认为是0.64x
- ❌ 看到"DTCM110"中的"110"就认为是工作距离110mm——实际官网物方WD=158±3mm
  （同系列56-AL是138±3，各不相同），该错误曾真实入库，靠refresh官网闭环才纠正
- ❌ 使用默认精度0.012mm而没有用户提供

**正确做法：**
- ✅ 向用户确认镜头倍率
- ✅ 从资料中提取精度要求

---

## 功能特性

1. **双重验证** - 精度验证 + 视野验证，确保选型结果完整可用
2. **Top 3方案** - 输出3个候选方案供用户选择
3. **模板继承** - 支持继承模板PPT的母版样式
4. **自动识别** - 自动识别工件尺寸、检测区域、视野
5. **型号可查证** - 所有硬件型号都有官网链接

## 快速开始

### 方式0：需求文本从0入口（弱模型推荐）

读用户图片/文档/口述后，把数字信息**原样抄录**给 `--text`，解析与口径判断交给脚本：

```bash
python tools/vision_proposal_generator.py \
  --text "设备精度≤0.03mm，生产节拍3秒，检测区域38.5x22mm，检测CD尺寸38.50±0.25..." \
  --output ./output --auto
```

漏填参数不会静默出错方案：脚本报`【缺少XX】`+可执行修正指引（exit=2），照提示补齐重跑即可。

### 方式1：使用模板PPT生成

```bash
python tools/vision_proposal_generator.py \
  --config project_config.json --output ./output --auto
```

模板可省略：依次找 `--template` 参数 → config 的 `template` 字段（相对路径按 config
所在目录解析）→ **自动扫描工作目录的 *.pptx**（取最新）。都没有时**只输出选型方案
结果并正常结束**（selection_result.json 照常落盘），放入模板后重跑同一命令即生成PPT。

### 方式2：从用户文件生成

```bash
python tools/vision_proposal_generator.py \
  --files 用户资料.jpg --template 模板.pptx --output ./output --auto
```

### 方式3：使用配置向导

```bash
python tools/config_wizard.py --output project_config.json
python tools/vision_proposal_generator.py --config project_config.json --auto
```

> 需求登记模板用 `config_template.json`（内嵌口径决策表；示例值均为 null，
> 禁止直接复制不改就跑）。标准作业流程（弱模型防呆）见 SKILL.md。

## 尺寸输入格式

系统支持多种输入格式，自动识别：

| 输入格式 | 识别类型 | 计算方式 |
|----------|----------|----------|
| `50x30x20` | 工件尺寸（长x宽x高） | 取长宽 × 余量系数 |
| `50x30` | 检测区域（宽x高） | 宽高 × 余量系数 |
| `fov:70x50` | 直接输入视野 | 直接使用，不加余量 |

---

## 工作流程

```
用户输入参数
    ↓
自动识别尺寸类型并计算视野
    ↓
精度验证 + 视野验证
    ↓
输出Top 3候选方案
    ↓
用户确认选择
    ↓
使用模板母版生成PPT
```

## 命令行参数

| 参数 | 说明 | 示例 |
|------|------|------|
| `--files` | 用户资料文件 | `--files image.jpg spec.pdf` |
| `--text` | 需求原始文字（从0入口，原样抄录数字信息） | `--text "设备精度≤0.03mm，节拍3s，检测区域38.5x22mm"` |
| `--config` | 配置文件路径 | `--config project_config.json` |
| `--template` | 模板PPT路径（可省略：config字段/工作目录自动发现） | `--template 模板.pptx` |
| `--output` | 输出目录 | `--output ./output` |
| `--auto` | 自动模式，**AI/弱模型调用必加**（非交互自动选最优方案） | `--auto` |
| `--hardware_page N` | 多视角模板只替换第N个硬件选型页（缺省全部） | `--hardware_page 1` |
| `--no_verify` | 跳过生成后自动验收（不建议） | `--no_verify` |
| `--wizard` | 使用配置向导（交互式） | `--wizard` |

## 输出文件（output\ 下）

| 文件 | 说明 |
|------|------|
| `方案PPT_时间戳.pptx` | 继承模板母版样式的方案PPT（验收通过后自动只保留最新版） |
| `selection_result.json` | 选型明细 + 19项核验结果（validation_passed 可信） |
| `acceptance_report.txt` | PPT规则自查报告（FAIL=0 才可交付，尾部带故障处置对照表） |
| `ppt_review\slide_N.png` | 每页渲染原图（1600px） |
| `ppt_review\overview.png` | 全页联系表总览（2列网格带页码，一眼看全） |
| `ppt_review\index.html` | 浏览器预览页（双击翻看，点击看原图） |

## 弱模型执行说明（模型能力要求与 token 账）

### 各环节由谁执行

| 环节 | 执行者 | 模型要做的 |
|------|--------|-----------|
| 需求解析/口径判断/参数校验 | 脚本 | 0（`--text` 原样抄字或填 config） |
| 选型计算/联动匹配/核验 | 脚本 | 0 |
| PPT生成/替换/验收/预览导出 | 脚本（主流程自动） | 0 |
| 旧版本PPT清理 | 脚本（验收通过自动清） | 0 |
| 无解诊断/口径混淆矫正 | 脚本（自动复核+提示） | 转述脚本的确认问题给用户 |
| 交付判断 | 模型看一行结论 | `FAIL=0` → 交付 |
| 向用户汇报 | 按工作区AGENTS.md模板 | 照抄填空 |

### 模型能力要求矩阵

| 场景 | 纯文本模型（无多模态） | 有视觉的弱模型 | 强模型 |
|------|:---:|:---:|:---:|
| 日常续跑交付（config已就绪） | ✅ 全程可跑 | ✅ | ✅ |
| 无模板纯选型 / 扩库查参数（网页文本） | ✅ | ✅ | ✅ |
| 新项目从0、资料为**文字/文档** | ✅（`--text` 抄录） | ✅ | ✅ |
| 新项目从0、资料为**图片**（产品照/图纸） | ❌ 需用户口述参数或换多模态模型 | ✅ 读图抄字 | ✅ |
| 预览图视觉终审 | ❌（不需要，见下） | ⚠️ 判断力有限 | ✅ |

**质量把关不依赖视觉**：check_ppt_quality 七项机检全部是 XML 解析+数值复算（零图像库依赖），
模型没有眼睛也能完成"生成→核验→自查→交付"闭环。预览图只是给人看的抽查材料。

### token 账（实测）

| 项目 | 消耗 |
|------|------|
| 全流程 stdout（一条命令跑完） | ~1900 tokens / 154 行 |
| 其中验收+预览环节 | ~129 tokens / 6 行 |
| 工作区 AGENTS.md「⚡最短路径」 | ~600 tokens |
| 按模板汇报 | ~200 tokens |
| **日常续跑全程合计** | **约 2000~3000 tokens** |

⚠️ **禁止模型读取 ppt_review\ 里的图片**——那是给用户看的预览。一张1600px页面图读入
即上千 token，7张全读比整个流程还贵，且机检已闭环、读图无必要。

### 防呆机制一览（弱模型踩过的坑，已全部脚本化拦截）

| 历史事故 | 现在的行为 |
|----------|-----------|
| 把"精度0.03"当像素精度→选型无解→死循环调参 | 无解诊断+口径自动复核+防死循环铁律输出 |
| 复制 config 模板不改就跑 | 模板示例值全 null，缺字段报错给可执行指引（exit=2） |
| 缺精度/尺寸时卡在交互输入 | 非交互环境直接报错+填写指引，不卡死 |
| 尺寸格式写错被静默按默认50x40算 | 报`【尺寸格式错误】`+正确格式示例 |
| config里模板填相对路径，cwd不对时模板"消失" | 按 config 所在目录解析相对路径 |
| 改 pixel_per_precision 等口径参数凑解 | 文档铁律禁止+脚本口径复核提示 |
| 从型号名"DTCM110"推断WD=110入库（实际158±3/138±3） | refresh官网闭环修正+wd_spec公差字段+README禁止型号推断 |

## 环境要求

```bash
pip install python-pptx Pillow numpy
pip install pywin32   # 可选：PPT预览图导出（PowerPoint COM）；缺省时自动降级
pip install easyocr   # 可选：OCR（图片资料建议AI直接读图，勿依赖）
```

预览导出通道自动降级：本机 PowerPoint COM（首选，后台无窗口）→ LibreOffice headless
转 PDF（已探测常见安装路径）→ 都没有时如实提示，不产出假预览。
